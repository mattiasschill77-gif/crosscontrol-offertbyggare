# v1.9.0 Quote Restyle and Whole-Unit Prices — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved quote-document restyle (no orange rule, 200 pt logo, +30 pt above the title, Helvetica/Arial, bold part numbers, spaced Unit price / Qty columns) and a "Round prices to whole units" checkbox, on all three document surfaces.

**Architecture:** The quote is rendered three times from one data contract — `renderDoc()` on screen, `buildPdfDocDefinition()` for pdfmake, `build_html()` in `generate_pdf.py` — so each visual change lands in three places. Rounding is decided in one function, `roundPricesOn()`, and applied where the document's money is produced: `fmtMoney` (decimals) and `lineTotalFromDisplayedUnit` (the line total is qty × the unit the customer reads). The export object carries `round_prices` so the two PDF renderers print the same figures the screen does.

**Tech Stack:** single-file HTML app, pdfmake 0.3.11 (inlined; standard-14 fonts supported via `PDFFontFactory`), WeasyPrint, pytest + Playwright + PyMuPDF (`tests/harness.py`).

Spec: `docs/specs/2026-09-17-v1.9-quote-restyle-and-whole-unit-prices.md`.

**Read first:** `CLAUDE.md`, `HANDOFF.md` §18.4 (running the suite; 8142 must be free), §27, §29.

- Never write an edit script as a bash heredoc (turns `\n` into a real newline and breaks the app). Use the Edit tool or write the script to a file.
