# Design spec — v1.8.0: customer address, optional list price, typed unit price, price list pagination

**Date:** 2026-09-08 · **Owner:** Mattias Schill
**Base:** `main` (`0df36ef`, v1.7.2, 91 tests)
**Branches:** `fix/pricelist-pdf-pagination`, then `feat/v1.8-quote-changes`
**Mockup approved 2026-09-08:** https://claude.ai/code/artifact/6f68afde-c37e-4d8c-af83-76a85fa538e5

Four changes: one defect in the price list PDF, and three requests from colleagues.
Released together as **v1.8.0**, in two branches — the pagination fix first, on its own,
because it is the only one touching a customer document that nothing else is changing.

---

## 1. What was asked

Three colleague requests, relayed by the owner on 2026-09-08:

> 1. That we should be able to insert a company address as well as the company name on the
>    Quote, just under the company name. For example Caudwell Marine, and then just under,
>    the address to the company.
> 2. Checkbox for showing list price or not.
> 3. Even if the user chooses a volume tier, the prices should be open for change if the
>    user chooses to do so. (Keep the deviation warning.)

Plus: **fix the price list PDF pagination.** The observed symptom is a family heading band
printing at the foot of a page while its products start on the next one.

## 2. Decisions

Every one of these is the owner's call, taken 2026-09-08 against the mockup. Do not
silently reverse them.

1. **The address is one multi-line free-text box**, not structured street/postcode/city
   fields. It prints as typed. Contact person and Country are untouched.
2. **The address appears on both documents**, and on the price list it gets **the quote's
   full TO block** — an orange `TO` label, the customer name in Poppins 16px, the address
   beneath, then `attn:`. The current `Prepared for X · attn: Y` subtitle line is replaced
   by that block. `Prepared by` (the KAM) is a different field and stays where it is.
3. **The list price checkbox is on the Quote tab and defaults to ON.** A colleague who
   never finds it must see the build they have today. The price list's own
   `Show list price & discount` toggle is untouched.
4. **A typed unit price wins over the tier price**, and Extra discount % is cleared and
   disabled while an override is active. One number decides the price, so the margin
   figure cannot be misread.
5. **⚠ deviation shows on any difference from the tier price**, above it as well as below.
6. **Clicking a tier chip keeps a typed price.** The chip changes the reference price, the
   MOQ and the document's tier tag; a stray click must never destroy a negotiated number.
7. **Cost and margin stay internal**, unchanged. A typed price changes what margin is
   calculated *from*; it changes nothing about where margin is *printed*, which is nowhere.

## 3. Change 1 — the customer address

### 3.1 Data

| | |
|---|---|
| Quote panel | new `<textarea id="custAddress" maxlength="300">` under `#custName`, with the standard character counter |
| Price list panel | new `<textarea id="plCustAddress" maxlength="300">` under `#plCustName`, same treatment |
| Quote export object | `customer.address` in `buildExportObj()` |
| Quote archive record | `customer_address` in `buildQuoteSnapshot()`, restored by `openQuote()`, cleared by the new-quote reset |
| Price list meta | `customerAddress` in `plGatherMeta()`, in the `PL_FIELD_MAP` id→meta table, and in the field list that `plOpenFromArchive()` restores |

300 characters with a live counter, matching the four fields bounded on 2026-08-25
(`HANDOFF.md` §18.2). An unbounded field that reaches a PDF block is the exposure that
deleted a Terms block once; a new one must not reopen it.

### 3.2 Rendering — four surfaces

- **Quote, screen** (`renderDoc()`): a `<div class="addr">` between `.billto .name` and
  `.billto .sub`, `white-space: pre-line`, 12px Arial, `--ink-700`.
- **Quote, pdfmake**: a `{ text: address, style: 'meta' }` node in the same position, with
  `lineHeight` matched to the screen block.
- **Quote, WeasyPrint** (`generate_pdf.py`): the same block in the f-string CSS and markup.
  ⚠️ `build_html()` shadows the `html` module with a local variable — the file imports
  `from html import escape as html_escape` for that reason; use it.
- **Price list, screen** (`plRenderDoc()`) **and pdfmake** (`buildPricelistDocDefinition()`):
  the subtitle line becomes a TO block, per decision 2.
- **Price list, Excel** (`plExportExcel`): the `Prepared for` header row is followed by one
  row per address line, the first labelled `Address`, the rest with an empty label cell.

There is **no** WeasyPrint path for the price list — `generate_pdf.py` renders quotes only.

### 3.3 Rules

- An empty address renders nothing at all. With the field blank, all four surfaces must be
  byte-identical to v1.7.2.
- The address is user text and is interpolated into HTML in `renderDoc()`, `plRenderDoc()`
  and `generate_pdf.py`. **It must be escaped in all three.** An archived record carrying
  `<img src=x onerror=…>` in the address executes on open, and archives move between
  colleagues (`HANDOFF.md` §20.2 — the same trap the quote number had).

## 4. Change 2 — the list price column, optional

### 4.1 Control

A checkbox `#showListPrice`, **checked by default**, in the Terms section beside
`#includeForecast`, using the existing `.pl-toggle-row` class.

⚠️ This differs from the mockup, which drew a new "Document options" card. There is no such
section in the app: `#includeSignature` lives in the signature section and
`#includeForecast` in Terms. Adding one would move two working controls for cosmetic
reasons. The checkbox goes where its sibling already is.

### 4.2 Behaviour

Unchecked removes, on screen and in both quote PDF paths:

- the `List Price` column header and every cell in it, including the custom-line `—`;
- the `+ N% negotiated discount` tag under the product name.

The tag goes with the column: a discount advertised off a price the customer can no longer
see is worse than either alone. Everything else is unchanged — the tier tag stays, because
"Tier 100-249 units" states the volume the price assumes, which is not a list price.

The state is stored as `show_list_price` in the export object and the archive record, and
restored on open. A quote reopened to be resent must have the shape it was sent in.

The Excel export and the price list are untouched.

## 5. Change 3 — a typed unit price over a volume tier

### 5.1 Model

One new field on a cart line: `unitPriceOverride` — a number in the **document currency**,
or `null`. `computeLine()` becomes:

```
tierPrice        = tiers[selectedTier].price_eur ?? listPrice      (unchanged)
finalUnitPrice   = unitPriceOverride != null
                     ? unitPriceOverride
                     : tierPrice * (1 - extraDiscountPct / 100)
lineTotal        = finalUnitPrice * qty
```

`computeTG()` already takes `finalUnitPrice`, so margin follows the typed price with no
change to it. The existing custom-line path (`item.isCustom`) is untouched — a custom line
already has its own price and no tier.

⚠️ **Currency.** The quote's prices are held in EUR and formatted through `fmtEUR()` at the
selected rate. A typed price is typed in the **displayed** currency, so it is divided by
the current rate on entry and stored in EUR, exactly as the displayed price is multiplied
on the way out. Changing currency after typing therefore converts the override rather than
reinterpreting it. A test pins this: type 245.00 in EUR, switch to SEK, and the line must
read the SEK equivalent — not 245.00 kr.

### 5.2 Controls, in the line card

- A `Unit price` input between the tier chips and Extra discount, showing the effective
  price. Empty placeholder = no override, showing the tier price greyed.
- While an override is active: the hint line `Typed price.` with a **Use tier price**
  button that clears the override, and the Extra discount input is set to `0`, `disabled`,
  and captioned `Cleared while a price is typed.`
- `⚠ deviation` shows when `unitPriceOverride != null && override !== tierPrice`, or, as
  today, when `extraDiscountPct > 0`. The flag text carries the signed percentage against
  the tier price, e.g. `⚠ deviation −4.7%`.
- Selecting a different tier chip **keeps** the override, recomputes the reference price
  and the deviation percentage, and changes the document's tier tag.
- Both inputs carry an `aria-label` naming the product, per the labelling contract
  (`HANDOFF.md` §11) — and note the **extra-discount input exists in two templates**
  (standard and custom line); the disabled state applies to the standard one only.

### 5.3 The document

Unchanged in shape. The Unit Price column prints the typed price, the tier tag stays, and
nothing indicates an override. The deviation flag and margin are panel-only, as now.

`unit_price_override` is carried in the export object and the archive record, and
`generate_pdf.py` needs no change beyond reading the already-computed `unit_price` — but
this must be verified against a real export, not assumed.

## 6. Change 4 — the price list PDF's stranded family heading

### 6.1 The defect

In `buildPricelistDocDefinition()` each family is pushed as **two independent content
nodes**: a one-row table holding the grey band, then the product table with
`headerRows: 1`. Nothing ties them, so a break can fall between them and the band prints
alone at the foot of a page.

### 6.2 The fix

Two parts, and the first is not sufficient on its own.

**1. Merge the band into the product table as its own header row**, so the table carries
`headerRows: 2`: row 0 is the band (one cell, `colSpan` across every column), row 1 is the
existing column header, and the product rows follow.

⚠️ **CORRECTED 2026-09-08, during implementation.** This section originally claimed the
merge was "structural rather than heuristic — there is no threshold to tune", on the
assumption that pdfmake cannot break between header rows and the body's first row. **That
assumption is false and was disproven by measurement.** pdfmake will happily render both
header rows at the foot of a page and start the body on the next one, which produces a
band *and* a column header dangling under nothing. It passed the guard once by luck of
layout, then failed the moment an unrelated fix changed the row heights.

**2. So the band is also tagged `headlineLevel: 'plFamily'` and a `pageBreakBefore`
callback moves a family whole** when the page has too little room left for its band, its
column header and one product row.

The threshold is measured, not estimated. `startPosition` carries `pageInnerHeight` and
`verticalRatio`, so the room left is `pageInnerHeight * (1 - verticalRatio)`. In a full
129-item price list the four families that dangled had **2.4, 60.9, 74.9 and 76.1pt** left,
while the closest legitimate multi-page family had **148.8pt**. A band plus column header
measures 77.7pt and one product row 36.3pt, so the requirement is ~114pt; `PL_FAMILY_MIN_BLOCK`
is set to **120**, in the middle of a clean 77–148pt separation.

⚠️ **Re-measure it if the band, the column header or the row padding changes.** Its whole
job is to be larger than band + header + row and smaller than the room a real family needs.

`pageBreakBefore` **relocates** a node and never holds or clips one, which is why it is safe
where the two options below are not.

⚠️ **It has a second, visible effect, and it is deliberate:** pdfmake repeats header rows
at the top of every page a table continues onto, so a family that spans a page break now
opens the next page with its own name above the column header, instead of with prices under
no heading at all. For a catalogue that is the better document. **Approved by the owner on
2026-09-08** ("repeating band is fine").

### 6.2b A second defect, found by looking at the render

Rendering the fixed PDF showed that the `PRODUCT | NET PRICE | MOQ` header appeared on the
**first family only**; every family after it got a blank row of the right height and no
column names — in a customer-facing document, in the shipped v1.7.2 build.

Cause: `cols` was one array of cell objects pushed **by reference** into every family's
table, and pdfmake writes layout state (`_width`, `_calcWidth`) onto cells as it renders, so
the first table consumed them. It is now a `makeCols()` factory returning fresh objects per
family; only `widths` is shared, and those are plain strings.

This is fixed here rather than deferred because `headerRows: 2` **repeats** the header on
every continuation page — without it the approved fix would have been repeating a blank row
down every long family. Pre-existing, not caused by this work.

⚠️ **Reported, not fixed:** the NET PRICE column is too narrow, so four-digit prices break
mid-number (`€1,002.8` / `0`) and the "NET PRICE" header wraps. Identical in v1.7.2.
Widening it changes the layout of every price list already sent, so it is the owner's call.

### 6.3 What this fix must not be

- ⚠️ **Not `unbreakable`.** pdfmake's `commitUnbreakableBlock` keeps only `pages[0]` and
  **discards the rest** — an over-tall block vanishes silently. That is how a quote once
  printed with no payment terms while the screen still showed them (`HANDOFF.md` §18.2).
- ⚠️ **Not `dontBreakRows: true`.** Row-level unbreakable, same failure: at a 3,279-character
  note the entire product row was deleted from the PDF while the totals kept counting it.
  It is forbidden in the quote builder and stays forbidden here.

### 6.4 Deliberately out of scope

Named so they are not mistaken for oversights. Each needs its own per-block height
measurement first, and skipping that step is what produced the defect above.

- Product rows fragmenting across the page edge — lossless, and pdfmake and WeasyPrint both
  do it.
- The `§` T&C block splitting across pages.
- The trailing footer-only page (`HANDOFF.md` §18.3).

## 8. Tests

Added to `tests/`, which stands at 91. **Every new guard is proven to go red with the thing
it protects broken, before it is trusted** — a green test that has never failed is not
evidence.

| Guard | Asserted on |
|---|---|
| The family heading is never last on a page | Extracted text of each PDF page: no page ends with a family name that has no rows under it |
| The address reaches the quote PDF | Address lines present in the extracted text of both PDF paths |
| The address reaches the price list PDF | Same, on the price list PDF |
| A blank address changes nothing | Byte-comparable page text against the v1.7.2 output |
| The address is escaped | An address containing `<b>` prints literally on screen and in both PDFs |
| List price off removes the price | €526.76 absent from the PDF text — not "the checkbox is unchecked" |
| List price off removes the discount tag | `negotiated discount` absent from the PDF text |
| The toggle survives a reopen | Archive round-trip |
| A typed price reaches the document | `245.00` and `36,750.00` in the PDF text |
| The total agrees with the visible lines | Subtotal equals the sum of the printed line totals |
| A typed price converts with the currency | Type in EUR, switch to SEK, assert the converted figure |
| A tier click keeps the override | Panel state after clicking another chip |
| Cost still never reaches a customer document | The existing decompressed-stream and workbook-XML scan, re-run with an override active |

⚠️ Traps that have produced false results in this suite before, and still apply:
PDF text extraction turns a line wrap into a double space, so normalise with
`re.sub(r"\s+", " ", t)` before asserting; a note made of one repeated character never
reproduces an over-tall row; Playwright's `fill()` respects `maxlength`, so a test needing
more than a user could type must go through `harness.set_value_bypassing_maxlength()`; and
the harness refuses to run if anything is already listening on 8142, because on Windows
`SO_REUSEADDR` would let it silently test the wrong build.
