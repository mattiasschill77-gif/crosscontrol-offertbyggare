# Design spec — v1.5.0

**Date:** 2026-08-25 · **Owner:** Mattias Schill · **Branch:** `feat/v1.5-version-pagination-i18n` · **Base:** `40ed9c9`

Five workstreams, requested in one sitting:

| | Workstream | Why |
|---|---|---|
| **A** | Version stamp | Tell at a glance which build is open |
| **B** | Header and footer on every page | A customer document must never lose its identity mid-way |
| **C** | Keep blocks whole across page breaks | A sentence must not be cut in half by a page edge |
| **D** | Document language EN / SV / DE | Sell to Swedish and German customers in their language |
| **E** | Chosen save location + locked archive copy | Save into a customer folder without losing the local backup |

Read `HANDOFF.md` first. This spec assumes its architecture, its brand system and its standing contracts.

---

## 1. Owner decisions — do not silently reverse

All taken 2026-08-25.

1. **The version goes in the app file name and in the topbar** — not in the quote's file name.
2. **The file in git keeps its name.** Only the delivered copies carry the version in the file name.
3. **A text block moves whole; a table breaks only between rows.**
4. **Language is chosen per document**, not globally. English is the default.
5. **Language affects the customer document only.** The app's own UI stays English.
6. **Legal wording stays English in every language** until CrossControl approves translations.
7. **Product descriptions stay English** until the workbook carries SV/DE columns.
8. **The local archive copy is always written.** It disappears only if the user deletes it in the archive.

## 2. A — Version stamp

**Single source:** `APP_VERSION = '1.5.0'` and `APP_BUILD_DATE = '2026-08-25'`, declared once at the top of the app script.

- **Topbar** sub-line becomes `Internal KAM tool · price list synced from Excel · v1.5.0`.
- **Delivered file name:** `crosscontrol-offertbyggare-v1.5.0.html` in Delivery, Demo kit and the Prototypes mirror. The repo file keeps the name `crosscontrol-offertbyggare.html` — renaming a 3.2 MB file every release makes the history unreadable.
- **Exactly one versioned file per delivery folder.** The previous file is *replaced*, never left beside the new one. The demo kit's `Fallback\` copy remains the only place an older build survives.
- `START HERE.txt` in the demo kit names the current file and must be updated on every release.
- **Internal stamping:** `app_version` and `app_build_date` go into `buildExportObj()`, the quote archive record and the price list archive record. **Never rendered in the customer document.**
- **git tag** `v1.5.0` on the merge commit. Minor bump per feature, patch per fix.
- `Current build - for comparison.html` is frozen on purpose: not renamed, not touched, not refreshed.

**Acceptance:** the topbar shows the version · an exported JSON carries `app_version` · the delivered files carry the version in their names · all four copies are identical by md5 · the tag exists in git.

## 3. B — Header and footer on every page

**Measured state before the change:**

| Output path | Header on every page | Footer on every page |
|---|---|---|
| `Download quote as PDF` (pdfmake) | ✅ `headerFn` called per page | ✅ `footerFn` called per page |
| `generate_pdf.py` (WeasyPrint) | ✅ `position: running(pageheader)` | ✅ `position: running(pagefooter)` |
| `Print via browser` | ❌ `.doc-header` is a normal block — page 1 only | ✅ `position: fixed` |

The quote's `pageMargins` are `[42, 92, 42, 132]`; the header and footer stacks fit inside them with room to spare. **No mechanism was found by which the pdfmake path can lose either.** If a PDF from that path turns up without them, it is a separate bug and belongs in this workstream.

**Work:**

1. **Browser print gains a repeating header** — `.doc-header` is given the same fixed-block treatment the footer already has, print-only, with matching top padding reserved on `.doc-body`. On-screen layout must not move, and neither PDF path may change.
2. **A regression test** (new, `tests/`) drives the real UI over `http://localhost:8142`, builds a quote and a price list that each run to three or more pages, downloads the PDF, and asserts **per page**: the logo image is present, `QUOTE #<id>` is present, the contact line is present, and `Page n of m` is present.
3. **Harness stack**, all three verified present on this machine 2026-08-25: Playwright drives Chromium against `python -m http.server 8142`, and `pypdf` / `PyMuPDF` read the downloaded PDF page by page. `file://` is refused by Playwright — always serve over localhost.
4. **The probe must be proven able to fail** before any pass is trusted — run it against a deliberately broken header (a temporary, uncommitted edit) and watch it fail first. A restored button label is not a pass signal; assert on the downloaded file.

**Acceptance:** the test passes on all three paths and has been observed failing on a broken build.

## 4. C — Keep blocks whole across page breaks

**The rule:** a text block moves whole to the next page; a table breaks only between rows and repeats its header row.

**Blocks that must not split** — quote: the § Terms & Conditions block including the 12-month forecast sentence, the terms grid, the totals block, per-line note paragraphs, the appendix note, every section eyebrow together with its first paragraph, and the signature block (already protected). Price list: a family heading with its first product row, the confidentiality note, the meta block, the professional details block.

**Per surface:**

- **pdfmake** — `unbreakable: true` on the wrapping stack. Tables get `dontBreakRows: true` and `headerRows: 1`.
- **Screen and browser print CSS** — `break-inside: avoid`, `break-after: avoid` on heading blocks, `orphans: 2`, `widows: 2`.
- **`generate_pdf.py`** — the same rules in its f-string CSS.

⚠️ **Never mark a block unbreakable that can exceed one page body height** (A4 minus the quote's margins ≈ 605 pt). pdfmake does not move such a block — it compresses or clips it. The product table and the price list family tables are therefore excluded by design and break between rows instead. A single note paragraph longer than a page will still split; accepted and documented.

⚠️ Every change here lands in **three** places. A change made in one surface only makes the PDFs diverge from the screen silently.

**Acceptance:** a quote deliberately built so that a break falls at each protected block produces no split block in any of the three paths · the product table still breaks between rows with its header repeated · orphan and widow control is visible in the printed output.

## 5. D — Document language (EN / SV / DE)

**Scope:** the customer document only — quote and price list, PDF and Excel. The app's own UI stays English.

**Selection:** `docLang` in the quote's Terms card and `plDocLang` in the price list's Professional details. Options: English (default), Svenska, Deutsch. Stored per document in the archive record and emitted as `doc_lang`.

**One dictionary.** `DOC_I18N = { key: { en, sv, de } }`, roughly 60 keys, declared once in the app script. `docT(key)` resolves against the active document language and falls back to English for a missing key.

⚠️ **Contract change to `buildExportObj()`.** It emits a resolved `labels` object — every document-visible string, already translated — alongside `doc_lang`. `generate_pdf.py` prints what it is given and **must not carry a dictionary of its own**; that is what keeps the translation out of the standing three-way duplication. An exported JSON without a `labels` object (anything archived before this release) falls back to the English literals already in the script, so old archives still render.

**Formats follow the language:**

| Language | Date | Number | Currency |
|---|---|---|---|
| English | `23 Nov 2026` | `1,234.56` | `€1,234.56` |
| Svenska | `2026-11-23` | `1 234,56` | `1 234,56 €` |
| Deutsch | `23.11.2026` | `1.234,56` | `1.234,56 €` |

Implemented with `Intl.DateTimeFormat` and `Intl.NumberFormat` (`sv-SE`, `de-DE`, and an explicit long-form day-month-year for English). ⚠️ **English deliberately does not use `23/11/2026`** — a US customer reads that as 11 March. Do not "simplify" it back to a slash format.

**Not translated in this release, by decision:**

- **Legal wording** — the T&C reference sentence, the 12-month forecast condition, the payment-terms presets, the VAT/tariff note and the Incoterms explainer. They stay English in all three languages. Gate: `LEGAL_TRANSLATIONS_APPROVED = false`. The SV and DE strings are written and sit unused behind it, so switching them on later is a one-line change rather than a new project. The panel shows an internal note naming which blocks are still English; **the customer document says nothing about it.**
- **Product descriptions** — they come from the workbook. Until it carries the columns, English is used and the panel reports coverage.

**Importer preparation** (ready ahead of the data, exactly as the MK column was): `PL_DESC_SV_RE` and `PL_DESC_DE_RE` match the start of the normalised header — `Description (SV)`, `Beskrivning (SV)`, `Description (DE)`, `Beschreibung`, `Bezeichnung (DE)`.

⚠️ **Collision risk.** `Benämning` is already the *primary* description header in the legacy Swedish workbook. A language-specific matcher must therefore **require an explicit language qualifier**; a bare `Benämning` or `Description` continues to feed the primary description and must not be captured as a translation.

**File names:** `quote-CC-2026-0001.pdf` for English, `quote-CC-2026-0001-sv.pdf` and `-de.pdf` otherwise. The price list follows the same pattern. The version does not appear here — see decision 1.

**Excel export:** column headers translated; the sheet name stays stable so downstream references do not break.

**Acceptance:** the same quote exported in three languages gives three PDFs where every non-legal label is correctly translated, dates and numbers follow the table above, the legal paragraphs are byte-identical English, and the product descriptions are identical · the archive round-trips the language · a quote archived before this release opens as English · the meeting spec for the workbook is extended with the SV/DE description columns beside the MK column.

## 6. E — Save location

**Environment:** `file://` in Chrome, opened from OneDrive. ⚠️ **Capability is unmeasured** — the File System Access API is very likely unavailable on `file://`, and IndexedDB may be too. The probe result decides which route is live, not which routes are built.

**One button, three behaviours:**

1. **API available** — `showSaveFilePicker` writes the PDF straight into the chosen folder. The folder handle is remembered per customer in IndexedDB when IndexedDB is available, otherwise for the session only.
2. **API unavailable** — the normal download runs. The dialog says plainly that the browser controls the destination, offers one-click copy of the customer's configured path, and points at Chrome's *Ask where to save each file* setting.
3. **Always, before either** — the archive copy is written to `localStorage` **first**, unconditionally. The archive checkbox renders checked and disabled.

Customer paths live in a new `cc_customer_folders_v1` store, keyed by customer name.

⚠️ **Detection must be feature-based** — `typeof window.showSaveFilePicker === 'function'`, plus a `try/catch` around the first real call. An API blocked by corporate policy can exist and still throw. The catch falls through to route 2 and **must not lose the file**.

**Acceptance:** on a machine without the API the file still reaches the user · with the API the file appears in the chosen folder · closing the tab straight after saving still leaves the quote in the archive · the archive checkbox cannot be unchecked.

## 10. Risks

| Risk | Mitigation |
|---|---|
| Renaming the delivered file breaks pinned shortcuts | One file per folder, `START HERE.txt` updated, previous build kept in `Fallback\` |
| An unbreakable block taller than a page compresses or clips | Only blocks that fit on a page are protected; tables break between rows |
| A language matcher swallows the primary description column | Language columns require an explicit qualifier in the header |
| File System Access API blocked by policy | Feature detection plus `try/catch`; the download route always remains |
| The three document surfaces drift apart | Every document change lands in `renderDoc()`, the pdfmake builder and `generate_pdf.py` in the same commit |
